# LifeOS 协作说明

## 当前阶段

产品内容与用户编辑入口：[LifeOS 产品结构文稿](LifeOS-产品结构文稿.md)。该文稿按页面列出原型内容，并提供用户修改区。它用于整理产品意图；具体实施范围以本文件的当前轮任务及用户最新明确要求为准，空白项不作为开发任务。

当前产品是 `index.html` 中的单文件交互原型。页面与 AI 回复主要是演示内容；健康记录与领域项目使用浏览器 `localStorage` 保存，没有后端。正式技术架构尚未确定，随用户确认的需求逐步制定。

## 分工

- 规划 agent：制定前后端架构、数据与接口约定、UI 体系，维护本文档中的每轮执行任务和验收标准，搭建所需公共骨架。
- 实现 agent：先读取本文档，根据当前轮已明确的任务修改业务页面或功能，并反馈变更文件、验证结果和未完成项。
- 用户：在预览中指出修改位置和期望效果，参与验收并决定后续迭代。
- 双方修改前重新读取相关文件；不得覆盖对方已有修改。每轮明确文件责任后再实施。

## 实时预览

在项目目录运行 `node preview.cjs`，打开 http://127.0.0.1:4173 。

预览服务只监听本机。保存 `index.html` 后，页面会自动刷新；刷新会重置原型中的临时交互状态。当前预览服务仅支持此单文件原型，后续拆分资源时需同步升级。

## 迭代流程

1. 用户指定页面、位置、期望行为或视觉效果。
2. 用户要求“写方案”时，规划 agent 直接更新本文件，写明本轮目标、问题原因、交互规则、修改范围和验收标准；除非用户同时要求实施，否则不修改页面代码。
3. 实现 agent 按本轮要求修改并报告验证结果。
4. 在预览中检查外观和交互；未通过的内容继续修正。
5. 验收通过后记录结果，进入下一轮。

## 当前轮任务

### 第 3 轮：领域项目保持独立选中状态

状态：方案已确认并写入 README，尚未修改页面代码。

#### 用户期望

- 点击哪个项目，就只高亮该项目。
- 其他领域中的项目不得因为共用同一个详情页面而一起高亮或一起熄灭。
- 项目选中状态与领域展开状态互不影响。
- 点击另一个项目时，高亮从原项目移动到新项目；每次最多只有一个项目处于选中状态。

#### 问题原因

当前侧栏项目通过两类页面路由打开详情：

- “AI 智能体开发”进入 `agent` 页面。
- 其他多数项目进入通用的 `simple` 页面。

现有 `render()` 使用 `data-page === current` 判断所有导航项是否高亮。由于多个不同项目都使用 `data-page="simple"`，进入其中任意一个项目时，所有指向 `simple` 的项目都会被视为当前项目。这是“多个项目同时亮起或熄灭”的根本原因。

页面路由只能表示“打开哪种页面”，不能作为项目的唯一选中标识。

#### 状态设计

导航需要明确区分三类状态：

| 状态 | 用途 | 建议标识 |
| --- | --- | --- |
| 当前页面 | 决定渲染领域页或详情页 | `current` / `data-page` |
| 当前项目 | 决定唯一高亮的项目 | `selectedProjectId` / `data-project` |
| 展开的领域 | 决定哪些项目列表可见 | `openAreas` / `data-sub` |

项目必须使用自己的唯一 ID 判断选中状态，例如 `p-lifeos`、`p-course`，不能再通过 `simple` 或项目名称判断。

#### 实施方案

1. 新增独立的 `selectedProjectId` 状态，保存用户最后点击的项目 ID。
2. 项目点击时同时更新 `selectedProjectId` 和详情页所需的 `pendingProject`。
3. 将 `render()` 中统一处理 `[data-page]` 的高亮逻辑拆分为 `updateNavState()`。
4. 普通导航与领域导航仍按照当前页面或当前项目所属领域判断高亮。
5. 项目子项只按照 `item.dataset.project === selectedProjectId` 判断高亮。
6. 只有正在查看 `simple` 或 `agent` 项目详情时才显示项目选中态；返回领域首页后不保留项目高亮。
7. 领域展开状态单独保存，不因切换项目、渲染详情页或更新项目高亮而改变。

建议的核心判断：

```js
const viewingProject = current === 'simple' || current === 'agent';

document.querySelectorAll('.subitem').forEach(item => {
  item.classList.toggle(
    'active',
    viewingProject &&
    item.dataset.project === selectedProjectId
  );
});
```

领域级高亮可根据当前项目反查：

```js
const selectedProject = projects.find(
  project => project.id === selectedProjectId
);

const activeArea = viewingProject
  ? selectedProject?.area
  : current;
```

#### 修改范围

- 只修改 `index.html` 中的项目点击处理、导航状态更新和领域展开状态。
- 不改变项目数据结构、项目卡片、详情内容、颜色体系或其他模块。
- 不通过增加特殊项目名称判断来解决问题。
- 不给每个项目创建一套重复详情页面。

#### 验收标准

1. 点击 LifeOS 时，只有 LifeOS 项目高亮。
2. 点击大学课程时，LifeOS 取消高亮，只有大学课程高亮。
3. 同属 `simple` 页面的多个项目不会同时高亮。
4. 点击 AI 智能体开发时，只有该项目高亮。
5. 切换项目不会自动展开或收起无关领域。
6. 返回领域首页后，项目子项不再显示为当前选中项目。
7. 新增项目、编辑项目、移动项目所属领域后，唯一选中逻辑仍然正确。
8. 桌面端和窄窗口侧栏行为一致。

### 第 2 轮：项目并入人生领域

状态：已实现，等待用户在预览中验收。

#### 产品结构

```text
人生领域
└─ 目标
   └─ 项目（可选）
      └─ 行动 / 任务
```

- “项目”不再作为工作空间中的独立导航，与“目标”并列。
- 事业、学习、健康、运动、财富和人脉六个领域各自展示属于自己的项目。
- 领域导航展开后显示该领域的项目，可直接进入项目详情。
- 项目保留执行能力，但必须归属一个领域；可关联目标，也可不关联。

#### 使用方式

1. 在左侧进入任意人生领域。
2. 在页面底部找到“领域项目”，点击“添加项目”。
3. 填写名称、所属领域、关联目标、状态、进度、截止日期和说明。
4. 项目卡片上的“编辑”可修改所有字段；“删除”会在确认后移除项目。
5. 顶部“新增 → 新建项目”和想法页的“转为项目”也会打开同一表单。

项目保存在当前浏览器的 `lifeosProjects` 本地数据中。刷新页面不会丢失；清除站点数据或更换浏览器后不会同步。正式产品应将同一数据结构迁移到后端账户存储。

#### 验收标准

1. 工作空间导航中没有独立“项目”入口。
2. 六个人生领域均有自己的项目区和添加入口。
3. 新增项目后，它出现在所选领域页面及该领域的侧栏子项中。
4. 编辑项目可修改所属领域；保存后项目移动到新领域。
5. 项目详情可返回所属领域并再次编辑项目。
6. 刷新页面后新增和修改的数据仍然存在。

### 第 1 轮：侧栏展开箭头位置与旋转修复

状态：已明确需求，待实现 agent 修改，尚未验收。

用户反馈：「事业发展」导航的展开箭头在动画后出现在按钮上方。预期箭头始终位于对应按钮内部右侧，与文字垂直居中。

#### 原因与公共 UI 约定

代码中 `.nav-item span,.nav-parent span{flex:1}` 同时作用于文字和 `.chev` 箭头容器。箭头容器被拉宽，旋转整个容器时，内部图标绕偏离自身中心的原点移动。这与截图中的偏移一致，需在浏览器中验证修复。

- 导航统一分成左侧固定图标、中间弹性文字、右侧固定箭头三个部分；只有文字占用剩余空间。
- 箭头容器固定为 14×14px，禁止 flex 拉伸和收缩，内部 SVG 居中并显式设置为 14×14px、块级显示。
- 只旋转箭头 SVG，以自身中心为旋转原点；收起朝右、展开朝下，保留约 180ms 的过渡，并遵守现有减少动画设置。
- 不使用负边距、绝对定位偏移或额外位移补偿掩盖布局问题。

#### 文件分工与实现范围

- 规划 agent 维护 `README.md` 中的要求与验收记录。
- 实现 agent 修改 `index.html` 的导航样式及必要的 `buildNav()` 标记，为导航文字增加明确的 class，替换笼统的 span 弹性规则。
- 检查所有可展开导航，避免只修事业发展；同时保持普通导航和底部设置入口的图标、文字对齐。
- 本轮保留原页面结构、色彩、导航点击跳转和展开收起行为，不做其他功能扩展。

#### 验收标准

1. 在事业发展以及其他可展开导航上反复点击，箭头在动画起始、中间、结束时均位于对应按钮内部右侧，不漂移、不跳到上一行。
2. 收起朝右、展开朝下；图标中心与文字所在行垂直居中，文字不被挤压。
3. 桌面侧栏、较窄窗口侧栏、移动端展开的侧栏均表现一致。
4. 普通导航、设置入口、子菜单和页面切换保持正常。
5. 实现 agent 反馈修改位置、实际检查的窗口与交互、修复后截图及任何未完成项；用户和规划 agent 查看预览后再标记验收通过。
